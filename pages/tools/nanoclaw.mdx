# NanoClaw

**Made by:** Community (Zig)
**Type:** Ultra-lightweight Agent Runtime
**Best for:** Edge deployments, embedded systems, serverless, anywhere size and startup time matter

<ConceptVideo id="tool-nanoclaw" title="NanoClaw: tiny but capable" />

## What it is

NanoClaw is an agent runtime built in Zig — a systems programming language optimised for performance and binary size. The result is remarkable:

- **678KB binary** — smaller than most favicons, smaller than a JPEG
- **< 2ms startup time** — faster than a blink
- **50+ provider integrations** — Telegram, Slack, Discord, email, REST APIs, and more
- **19 channel types** — every major messaging platform
- **Zero runtime dependencies** — the binary is the entire runtime

It's OpenClaw's smaller, faster sibling. Where OpenClaw prioritises features and extensibility, NanoClaw prioritises footprint and speed.

<Callout type="info">
NanoClaw is ideal when you need agents that start instantly, cost almost nothing per instance, and can run anywhere — from a Raspberry Pi to a Cloudflare Worker to a Kubernetes pod.
</Callout>

## Why size and startup time matter

Most agents run in the cloud where resources are plentiful. NanoClaw targets the cases where that's not true:

**Serverless functions** — Cold starts are the enemy. A 678KB binary starting in 2ms vs a Node.js runtime taking 800ms is a meaningful difference at scale.

**Edge computing** — Running agents close to users (Cloudflare Workers, Fastly Compute) requires extreme size constraints.

**Embedded systems** — IoT devices, industrial controllers, smart appliances — these can now run agents.

**High-concurrency deployments** — When you're running thousands of agent instances simultaneously, footprint per instance adds up fast.

**Kubernetes pods** — A pod image with NanoClaw can be 5MB vs 500MB for a Node.js equivalent. Faster pod startup, lower registry costs, faster scaling.

## Quick start

<Steps>

### Install NanoClaw

```bash
curl -fsSL https://nanoclaw.dev/install | bash

# Verify installation
nanoclaw --version
```

### Create a minimal config

```toml
# agent.toml
[agent]
name = "my-agent"
model = "claude-sonnet-4-5"
system_prompt = "You are a helpful assistant."

[channels.telegram]
bot_token = "${TELEGRAM_BOT_TOKEN}"
```

### Run your agent

```bash
TELEGRAM_BOT_TOKEN=your_token nanoclaw --config agent.toml
```

Your agent is now live on Telegram. Total setup time: under 5 minutes.

</Steps>

## Configuration reference

NanoClaw uses a TOML config file. Here is a complete example showing all major features:

```toml
[agent]
name = "my-nanoclaw-agent"
model = "claude-sonnet-4-5"
system_prompt = """
You are a helpful operations assistant. You monitor systems, answer questions,
and escalate urgent issues to the on-call team.
"""

# Multiple channels — agent listens on all of them simultaneously
[channels.telegram]
bot_token = "${TELEGRAM_BOT_TOKEN}"

[channels.slack]
token = "${SLACK_BOT_TOKEN}"
signing_secret = "${SLACK_SIGNING_SECRET}"

[channels.webhook]
port = 8080
path = "/agent"

# Persistent memory with full-text search
[memory]
type = "sqlite"
path = "./agent.db"
max_entries = 10000
search = "bm25"   # BM25 relevance ranking

# Scheduled tasks — no external cron needed
[[schedules]]
cron = "*/5 * * * *"
task = "Check monitoring alerts and notify if anything is critical"

[[schedules]]
cron = "0 8 * * 1-5"
task = "Send morning standup summary to the #ops Slack channel"

# Sub-agent delegation
[[tools]]
type = "delegate"
agent = "research-agent"
config = "./research-agent.toml"
```

## Memory

NanoClaw uses SQLite with FTS5 for agent memory — the same search primitives that power enterprise search engines. Agents can store and retrieve information with full-text search, ranking, and fuzzy matching — all in a 500KB database file with no server required.

```toml
[memory]
type = "sqlite"
path = "./agent.db"
max_entries = 10000
search = "bm25"   # BM25 relevance ranking
```

Memory persists across restarts automatically. The agent builds knowledge over time without needing an external vector database or memory service.

## Sub-agents (delegate tool)

NanoClaw supports **sub-agent delegation** — an agent can spin up another NanoClaw instance, give it a task, and incorporate the result:

```toml
[[tools]]
type = "delegate"
agent = "research-agent"
config = "./research-agent.toml"
```

This enables multi-agent patterns even in resource-constrained environments. Because each NanoClaw instance starts in under 2ms, spawning a sub-agent has negligible overhead.

### Example: supervisor + specialist pattern

```toml
# supervisor.toml
[agent]
name = "supervisor"
model = "claude-sonnet-4-5"
system_prompt = """
You coordinate research tasks. When asked a complex question,
delegate research to the research agent and synthesis to the writer agent,
then combine their outputs into a final answer.
"""

[[tools]]
type = "delegate"
agent = "researcher"
config = "./researcher.toml"

[[tools]]
type = "delegate"
agent = "writer"
config = "./writer.toml"
```

```toml
# researcher.toml
[agent]
name = "researcher"
model = "claude-haiku-4-5"
system_prompt = "You gather facts and data. Return structured findings."

[[tools]]
type = "web_search"

[[tools]]
type = "http"
```

## Deployment patterns

<Tabs items={['Bare metal / VM', 'Docker', 'Kubernetes', 'Serverless']}>
<Tab>
```bash
# Download the binary (one file, 678KB)
curl -fsSL https://nanoclaw.dev/install | bash

# Run with a config file
nanoclaw --config agent.toml

# Run as a background service
nanoclaw --config agent.toml &

# Recommended: use systemd for production
sudo tee /etc/systemd/system/nanoclaw.service <<EOF
[Unit]
Description=NanoClaw Agent
After=network.target

[Service]
ExecStart=/usr/local/bin/nanoclaw --config /opt/agent/agent.toml
Restart=always
EnvironmentFile=/opt/agent/.env

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now nanoclaw
```
</Tab>

## NanoClaw vs OpenClaw

| | NanoClaw | OpenClaw |
|---|---|---|
| Binary size | 678KB | ~15MB |
| Startup time | < 2ms | ~200ms |
| Language | Zig | Go |
| Config format | TOML | YAML |
| Plugin system | Built-in providers | External plugins |
| Extensibility | Compile-time | Runtime |
| Best for | Edge, serverless, embedded | Feature-rich, extensible |

<Callout type="info">
A common pattern is to use NanoClaw as the **edge listener** — fielding incoming messages and routing them — while delegating complex, long-running tasks to an OpenClaw or Scout agent. NanoClaw's 2ms startup makes it ideal for the hot path.
</Callout>

## When NanoClaw makes sense

- You're running **hundreds or thousands** of agent instances
- You need agents on **serverless** (Lambda, Cloud Functions, Workers)
- You're deploying to **IoT or embedded** hardware
- You need the **fastest possible response time** to user messages
- You want the **simplest possible deployment** (one file, no dependencies)
- You're building an agent that runs as a **Telegram or Discord bot** and needs to be always-on with minimal cost

## Common patterns

### Always-on Telegram bot

The simplest NanoClaw deployment — a bot that responds to messages 24/7 from a single 678KB binary:

```toml
[agent]
name = "support-bot"
model = "claude-haiku-4-5"
system_prompt = """
You are a customer support agent for Acme Corp. Answer questions about our
products, check order status (tool: check_order), and escalate complex issues
by saying ESCALATE: <reason>.
"""

[channels.telegram]
bot_token = "${TELEGRAM_BOT_TOKEN}"

[memory]
type = "sqlite"
path = "./support.db"

[[tools]]
type = "http"
name = "check_order"
url = "https://api.acme.com/orders/{order_id}"
auth = "Bearer ${API_KEY}"
```

### Edge monitoring agent

Run NanoClaw at the edge, close to your infrastructure, with near-zero overhead:

```toml
[agent]
name = "monitor"
model = "claude-haiku-4-5"
system_prompt = """
You monitor infrastructure metrics. When you detect anomalies, send alerts
to the ops Slack channel with severity level and recommended actions.
"""

[[schedules]]
cron = "*/1 * * * *"
task = "Check all service health endpoints and alert on failures"

[channels.slack]
token = "${SLACK_BOT_TOKEN}"
default_channel = "#alerts"

[[tools]]
type = "http"
name = "health_check"
```
