# Step 7 — Clawvisor

*For agents:* Connect each integration your human uses. Follow the exact steps for each one. Verify with a live test before marking it done. Save connection status to TOOLS.md.

---

Clawvisor is the integration layer — the bridge between your Claw and the tools you actually work in every day. Without it, your Claw lives in a chat window. With it, it can read your email, check your calendar, post to Slack, open GitHub issues, and act across your entire stack.

## Environment check first

The connection steps differ slightly between HyperClaw and OpenClaw. Check which you're on:

```bash
openclaw status
```

| Environment | How to connect integrations |
|---|---|
| HyperClaw | Dashboard → Your Claw → Clawvisor → Connect |
| OpenClaw | `openclaw configure` → select integration |

The steps below cover both paths.

<Steps>

### Connect Google Workspace (email + calendar)

Google Workspace covers both Gmail and Google Calendar in one OAuth flow.

**HyperClaw:**
1. Go to Dashboard → Your Claw → Clawvisor
2. Click *Google Workspace* → *Connect*
3. A browser tab opens — sign in with your Google account
4. Grant the requested permissions (read/send email, read/write calendar)
5. You'll be redirected back to the dashboard with a green "Connected" status

**OpenClaw:**
```bash
openclaw configure
# Select: Google Workspace
# Select: Gmail + Google Calendar
# A browser tab opens — complete the OAuth flow
# You'll see: "Google Workspace connected successfully"
```

**Verify email:**
```text
What are the last 3 unread emails in my inbox? Show me the subject and sender.
```

**Verify calendar:**
```text
What do I have scheduled for tomorrow?
```

Both should return real data from your account. If either fails, see [Troubleshooting → Clawvisor](/onboarding/troubleshooting#step-7--clawvisor).

<Callout type="info">
Your Claw reads and sends email only when instructed — it does not passively monitor your inbox unless you set up a scheduled task to do so.
</Callout>

Once calendar is connected, update your morning brief to include today's events:

```text
Update my morning-brief skill to add a "On the calendar" section with today's events.
```

### Connect Slack

**HyperClaw:**
1. Dashboard → Clawvisor → Slack → Connect
2. Select the workspace and grant permissions
3. Choose which channels your Claw can read and post to — start with 1–2, not all

**OpenClaw:**
```bash
openclaw configure
# Select: Slack
# Enter your Slack workspace URL (e.g. yourteam.slack.com)
# Complete the OAuth browser flow
# Grant: channels:read, chat:write, channels:history
```

**Verify:**
```text
Post "Claw connected ✅" to #[any low-traffic channel].
```

The message should appear in Slack within a few seconds.

<Callout type="warning">
Channel names are case-sensitive and must match exactly. `#dev-general` ≠ `#Dev-General`. If the post fails, check the exact channel name in Slack.
</Callout>

### Connect GitHub

GitHub access can be set up via OAuth or a Personal Access Token (PAT). PAT is simpler and easier to scope precisely.

**Create a PAT:**
1. Go to github.com/settings/tokens → *Generate new token (classic)*
2. Set expiry (90 days is reasonable)
3. Select scopes: `repo` (full) or at minimum `contents:read`, `pull_requests:write`, `issues:write`
4. Copy the token

**Set the token in your Claw:**

HyperClaw:
```text
Set my GitHub token to [paste token]. Store it as GH_TOKEN in my environment.
```

OpenClaw:
```bash
openclaw env set GH_TOKEN=ghp_your_token_here
```

**Verify:**
```text
List the open pull requests in [owner/repo-name].
```

Your Claw should return real PR titles and numbers.

<Callout type="warning">
Grant repo-level access, not org-level, until you've verified your Claw behaves correctly. Expand later once you've built trust in how it handles repo operations.
</Callout>

## What Clawvisor unlocks

Once connected, your Claw can coordinate across your full stack without you switching context:

| What you say | What your Claw does |
|---|---|
| "Clear my morning" | Reads calendar, drafts decline messages for low-priority meetings |
| "Catch me up on Slack" | Surfaces threads where you were mentioned since yesterday |
| "Handle the support emails" | Reads inbox, drafts replies, flags anything that needs you |
| "What's open on the repo?" | Lists PRs and issues, grouped by recency |
| "Send the brief to the team" | Publishes to ZenBin and posts the link to Slack |

Each of these combines two or more integrations — which is why Clawvisor is core setup, not optional.

## Add more integrations

Connect these as your workflows require:

- *Notion* — read and write to your workspace: meeting notes, wikis, project databases
- *Linear / Jira* — create issues, update statuses, and surface blocked work
- *Zoom / Meet* — join calls, generate summaries, create action items from transcripts
- *Stripe / QuickBooks* — monitor revenue, flag anomalies, pull financial context into briefs
